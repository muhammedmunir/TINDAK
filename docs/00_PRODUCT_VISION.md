# 00 — PRODUCT VISION

**Product:** TINDAK  
**Tagline:** Jumpa sesuatu. Tindak terus.  
**Platform:** Android first  
**Owner:** Product Direction (ChatGPT)  
**Approval:** CEO  
**Status:** READY FOR CEO APPROVAL

## 1. Vision
TINDAK turns useful information encountered on a phone into an immediate next action.

```text
SHARE → UNDERSTAND → ACT → REMEMBER → PROTECT
```

TINDAK is an **action layer for useful information received or discovered on an Android phone**.

## 2. Problem
Important information arrives through WhatsApp, Telegram, browsers, email, SMS and notes. Users often read it, postpone action, and forget.

TINDAK changes:

```text
Receive → Read → "Later" → Forget
```

into:

```text
Receive → Share to TINDAK → Understand → Act → Save when wanted
```

Example: `Bayar bil TNB RM183.50 sebelum 25 September.` TINDAK should identify the amount and date and offer useful actions without making the user recreate the information manually.

## 3. Target Users
Primary: Malaysian Android users who frequently receive actionable information through messaging, links and everyday digital communication.

Initial useful segments include students, office workers, freelancers, small-business users and family users.

## 4. Malaysia-First Wedge
V1 prioritizes Malaysian usage patterns:
- Malaysian phone formats.
- RM/MYR.
- DD/MM/YYYY numeric dates.
- Bahasa Melayu, English and common mixed-language input where supported.
- WhatsApp, calls, reminders and URL actions.

Malaysia-first is an initial wedge, not a permanent geographic limitation.

## 5. Product Principles
1. **Explicit user control.** The user chooses what TINDAK sees and what it remembers. Share does not mean Save.
2. **Local first.** Simple understanding and core actions work locally where practical.
3. **Guest first.** First-use value must not require an account.
4. **Offline useful.** Core local understanding, local Memory and supported actions remain useful offline.
5. **One Memory experience.** Users should not need to understand local-vs-cloud database architecture.
6. **Privacy by default.** No automatic saving, automatic external URL reputation lookup, or automatic cloud-AI processing.
7. **Explainable security.** Risk levels require reasons; no invented scam certainty.
8. **Minimal before intelligent.** Prove the core loop before OCR, semantic search or proactive AI.

## 6. What TINDAK Is Not
V1 is not a generic AI chatbot, full task manager, finance tracker, screenshot manager, standalone antivirus/scam app, background clipboard reader, social network, productivity dashboard, knowledge graph or universal automation platform.

## 7. Memory Philosophy
Memory is user-controlled. Guest users can save locally without an account. Cloud synchronization becomes available after authentication.

Unsynced guest data may be lost if the app is uninstalled or app data is cleared. This must be communicated clearly without blocking first use.

## 8. AI Philosophy
AI is a fallback, not the product identity. Before first cloud-AI processing, TINDAK discloses that content may be sent to a cloud provider and obtains consent. Declining AI must not disable local functionality.

## 9. Protect Philosophy
External URL security/reputation checks are user-triggered in V1.

```text
URL detected → [Open] [Security Check] [Save]
```

## 10. Magic Moment
Activation occurs when:

```text
User shares content
        ↓
TINDAK understands something useful
        ↓
User performs a relevant action
```

## 11. North Star Metric
**Successful Actions per Weekly Active User.**

TINDAK succeeds when users develop the habit: **“This is useful. I’ll share it to TINDAK.”**
